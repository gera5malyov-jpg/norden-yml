# Поставщик Norden — правила загрузки категорий в Яндекс KIT

Актуальная версия: 24.09.2026.

Этот файл дополняет общий регламент загрузки поставщиков. Для Norden правила ниже имеют приоритет.

## Категории

1. Не копировать дерево категорий Norden в KIT как есть.
2. Никогда не создавать категорию или корневой раздел `Norden`. Norden — бренд/поставщик, а не категория товара.
3. Серии и коллекции (Sigma/Сигма, Allegro/Аллегро, Prizma/Призма, Atlas/Атлас, Reef/Риф, Oliver/Оливер и др.), цвет, материал, размер/тип опоры, количество уровней и аналогичные признаки хранить как характеристики товара, а не как уровни каталога.
4. Для нового товара сначала определить точный исходный путь категории Norden, затем применить только согласованное правило из `norden-kit/category_policy.json`.
5. Разрешено автоматическое назначение категории только при точном совпадении с правилом с высокой уверенностью. Нечёткое/fuzzy-сопоставление запрещено.
6. Если точного согласованного правила нет, не создавать новую категорию и не помещать товар в произвольную существующую категорию. Такой товар должен попасть в отчёт как `CATEGORY_REVIEW_REQUIRED` для ручного согласования.
7. Согласованный путь назначения является полным путём KIT. При необходимости можно создать недостающие узлы именно этого согласованного пути, но нельзя расширять дерево собственными промежуточными разделами.
8. Для существующего товара автоматическая синхронизация цены/остатка не должна менять категорию, если для текущего исходного пути нет точного согласованного правила.
9. После добавления нового правила сначала выполнить smoke-test на одном товаре и перечитать карточку из KIT. Проверить `category_ids`, название категории и полный путь.
10. В отчёте показывать: исходный путь Norden, итоговый путь KIT, применённое правило, число перенесённых товаров и список товаров, требующих проверки.

## Зафиксированные правила

Источник истины: `norden-kit/category_policy.json`.

В нём сохранены только проверенные высокоуверенные соответствия, согласованные 24.09.2026. Если позднее пользователь подтвердит дополнительные категории, добавлять их в этот файл отдельным изменением и не менять уже согласованные правила без прямого указания пользователя.

## Защита от регрессии

Перед созданием товара:
- вычислить правило категории;
- если результат = REVIEW/нет правила — товар автоматически не создавать;
- если правило найдено — использовать согласованный конечный путь;
- не использовать fallback `["Norden"]`;
- не использовать исходный путь Norden как fallback.

Изменение этих правил допускается только по новой явной инструкции пользователя.

## Автоматическое обновление кресел и стульев — 24.09.2026

Последнее прямое правило пользователя; имеет приоритет над более ранними правилами Norden, если они противоречат этому разделу.

1. Автоматизация работает пока только для фактических кресел и стульев Norden. Аксессуары, чехлы, подголовники, подлокотники, запчасти и комплектующие не включать.
2. Периодичность — каждые 6 часов.
3. Цепочка: полный источник Norden → лист Google Sheets «Норден» → Webasyst → Яндекс KIT.
4. В таблице артикул поставщика Norden сопоставлять с колонкой «YML ID». Для идентификатора разрешена техническая нормализация пробелов, дефисов, слешей и визуально смешанных кириллических/латинских символов. Не использовать название для автоматического объединения.
5. Если идентификатор неоднозначен или есть потенциально похожая старая позиция, не создавать дубль: вынести товар в отчёт на ручную проверку.
6. При полном корректном каталоге товар из управляемого набора, которого больше нет у поставщика, получает остаток 0. Его прежние закупочные/продажные цены не очищать и не пересчитывать.
7. Если источник неполный, аварийно мал или загрузка источника не подтверждена, массовое обнуление запрещено.
8. Новые товары: сначала добавить строку в таблицу. Затем создать товар в Webasyst. Артикул, сформированный Webasyst, записать в колонку «Артикул» таблицы и использовать этот же артикул в KIT.
9. Webasyst:
   - тип товара: NORDEN-100;
   - категорию новому товару не назначать;
   - сопоставление существующих карточек — по «Артикулу»;
   - склад — «Основной склад»;
   - закупочная цена = оптовая цена Norden;
   - цена продажи = закупка × 1,23;
   - зачёркнутая цена = закупка × 1,65;
   - остаток = сумма разрешённых складов Norden МСК + СПБ;
   - у исчезнувшего товара только остаток 0, цены сохранять.
10. KIT:
   - сопоставление существующих карточек — по «Артикулу»;
   - склад «МСК» получает остаток «Основной склад» Norden;
   - склад «СПБ привозной» получает остаток «Питер Основной склад» Norden;
   - цена продажи = закупка × 1,26;
   - зачёркнутая цена = закупка × 1,65;
   - минимальную цену этим процессом не менять;
   - у исчезнувшего товара оба управляемых остатка 0, цены сохранять.
11. Новую карточку KIT создавать только если для исходного пути категории Norden есть точное согласованное правило в norden-kit/category_policy.json. Если правила нет — товар оставить без создания в KIT и вынести в отчёт CATEGORY_REVIEW_REQUIRED на согласование пользователя.
12. Существующим карточкам этим процессом не менять название, описание, фото, характеристики или категории; только разрешённые цены и остатки.
13. Для новых карточек переносить максимально полный корректный публичный контент источника по мастер-регламенту, без НДС, публичной характеристики «Поставщик» и характеристик остатков.
14. Глобальный STOP_ALL_NORDEN для старых/наследуемых Norden-процессов сохранять. Данная 6-часовая автоматизация должна быть отдельной и ограниченной указанным контуром.
