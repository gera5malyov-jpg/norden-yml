# А.Р. ИМПЭКС - выгрузка для YML Pro

Источник: https://arimpex.ru/sitemap/sitemap_products.xml

Скрипт `arimpex/parser.py` обходит все модели из официального sitemap, извлекает полные списки реальных модификаций через `/api/product/<eid>/offers/`, поскольку HTML содержит только часть вариантов, и загружает каждую модификацию отдельной карточкой товара. Например, TUKA CB1994 имеет 57 реальных SKU (19 сидений × 3 каркаса), а не один из первоначального HTML. Переносятся актуальная цена, старые цены (когда есть), характеристики, конфигурация материалов, фотографии и доступный остаток.

**Постоянная ссылка на YML после успешного первого запуска:**

https://raw.githubusercontent.com/gera5malyov-jpg/norden-yml/main/arimpex/arimpex.yml

Расписание: GitHub Actions `.github/workflows/arimpex-weekly.yml`, каждые 6 дней начиная с 18.10.2026, в 04:24 UTC (07:24 Москвы). Для точного шестидневного интервала GitHub проверяет календарь ежедневно, но парсер запускается только в нужную дату (18.10, 24.10, 30.10, 05.11 и т.д.). Ручной запуск через `workflow_dispatch` и внеплановые запуски при изменении кода парсера сохранены.

Сопоставление YML Pro: идентификатор предложения `arimpex-<ID модификации>`. Каждый вариант имеет свой уникальный `vendorCode` формата `ARIMPEX-<ID>`, а исходный артикул модели хранится в `model` и параметре «Артикул производителя». Атрибут `group_id` намеренно не передаётся: YML Pro должен создавать каждую комбинацию как отдельный товар, а не объединять несколько артикулов в одну карточку. В `name` входят характеристики конкретной конфигурации, а `model` хранит исходный артикул модели.

`count` передаётся из фактического доступного остатка. Статус «Под заказ» не приравнивается к физическому наличию, поэтому `count=0`, но `available=true` (заказ допустим). Для неизвестных или недоступных статусов `available=false`.

К фотографиям каждой отдельной модификации добавляются ссылки на её собственные образцы материалов из конфигуратора (например, квадрат цвета сиденья и образец отделки каркаса). Основные фотографии идут первыми, образцы - следующими `<picture>`. Образцы не смешиваются между модификациями. Изображения преобразуются из URL imgproxy в постоянные оригинальные ссылки, когда такое преобразование возможно. В GitHub не скачиваются фотографии, используются ссылки. Скрипт не использует KIT и API Webasyst, и не меняет данные магазина. При любой ошибке получения модификаций или подозрительном сокращении каталога старый YML не перезаписывается.
